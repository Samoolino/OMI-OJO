# S6B — Builder / Grant Evidence Package

## Objective

Present OMI-OJO as a reproducible environmental evidence infrastructure build with measurable technical work packages. This document is an evidence package specification, not evidence of an awarded grant or investment.

## Demonstration proposition

Environmental source → Provider provenance → Reconciliation → DMRV package → Deterministic evidence root → Blockchain anchor → Public verification → VDR

The system demonstrates integrity and reproducibility. It does not manufacture environmental truth through blockchain.

## Application evidence index

Every controlled application should link to:

1. project scope and objectives;
2. production map;
3. institutional production framework;
4. DMRV schema and indicator mapping;
5. provider/reconciliation architecture;
6. blockchain contract and S6A specification;
7. reproducibility tests;
8. security review;
9. deployment receipt when available;
10. public verification demonstration;
11. budget and milestones;
12. risk register;
13. claims boundary;
14. physical-production separation.

## Funding status vocabulary

PROPOSED → SUBMITTED → UNDER_REVIEW → AWARDED

Alternative terminal states: DECLINED or WITHDRAWN.

No interface, investor document or repository status may display a funding award unless documentary evidence has been attached to the VDR.

## Budget discipline

Requested support should be expressed as measurable infrastructure:

- engineering;
- data/provider integration;
- testnet deployment and controlled gas;
- security review;
- verifier development;
- evidence/VDR tooling;
- monitoring;
- documentation;
- authorized field-validation preparation where explicitly eligible.

Do not convert a technical infrastructure budget into unsupported token value or environmental-credit value.

## Builder-resource request

Where a network ecosystem provides developer support, the request should distinguish testnet/native gas resources, developer credits, infrastructure credits, accelerator/build support, and direct grant funding.

## Release gate

S6B is ready for controlled applications when the application can demonstrate the complete digital lifecycle with retained evidence. Funding remains external to the repository and must be recorded only after documentary confirmation.

## Physical transition

A successful S6B application does not authorize water collection. Physical Premium RainWater remains NOT_RELEASED until site authorization, collector/QMS controls, controlled rain event, laboratory/QMS review, batch/seal provenance, DMRV and release review are complete.
