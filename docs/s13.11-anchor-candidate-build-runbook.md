# S13.11 — Blockchain Anchor Candidate Build

## Purpose
Construct the deterministic candidate record that could anchor a reconciled S13 event package using the project's evidence-anchor registry.

This gate prepares an anchor. It does not claim that a blockchain transaction has occurred.

## Preconditions
- S13.10 reconciliation is complete within the defined scope.
- Material reconciliation exceptions are resolved or explicitly dispositioned.
- The package digest is locked.
- Anchor schema, network and contract target are known.

## Procedure
1. Confirm the S13.10 reconciliation conclusion.
2. Freeze the package digest and package version.
3. Define the anchor scope and event identifier.
4. Register methodology/schema versions and contract/network target.
5. Build the deterministic candidate from the locked package digest and metadata.
6. Validate candidate digest, package linkage and lineage.
7. Record candidate construction timestamp and responsible identity.
8. Preserve the candidate record for independent review.
9. Do not represent a transaction hash, block number or confirmation as present unless the transaction is actually submitted and confirmed.

## Evidence boundary
The anchor candidate is an integrity/reference record. A blockchain anchor can demonstrate that a particular package representation was committed or referenced; it does not establish the truth of the environmental evidence, laboratory results, premium condition, certification or product release.

## Fail-closed
Do not build or advance a candidate when reconciliation is incomplete, the package digest is missing, scope/version metadata is unresolved, lineage fails, or the target registry/network is ambiguous.
